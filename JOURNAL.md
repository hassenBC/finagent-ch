# Journal

One line per session: what I tried, what I measured, what surprised me.

- 2026-11-05 — Phase 0: repo scaffold, Postgres+pgvector in Docker, cached LLM client (DeepSeek), vast.ai GPU scripts.
- 2026-11-06 — Dropped vast.ai: embeddings/reranking on the laptop GPU (RTX 3050 Ti, 4 GB), self-hosted LLMs via Ollama. torch 2.13 on CUDA 12.9 wheels (driver 555 only supports CUDA 12.5).
- 2026-11-06 — Phase 1: 12 reports (6 banks x FY24/25), 2,881 pages, 18,098 chunks (fixed512 4,546 / structure 5,699 / table_aware 7,853); no chunk over the token cap. Docling takes ~5-8 min per 250-page report on the 3050 Ti; heading levels all come back as 1, so `section_path` is only the latest heading, not a hierarchy.
- 2026-11-06 — Parse quality (20 random table chunks, seed 42): at least 3 confirmed wrong against the PDF page, all header problems — multi-level header merged into one cell (JB 2024 p206), header merged into the first data row (EFG 2024 p150), continuation table with no column header (JB 2025 p151). Only those 3 were checked visually (picked because the Markdown looked off); the other 17 were read as Markdown only, so the real error rate is >= 15% and not yet measured properly. Table-aware chunking repeats the header row, which makes bad headers worse.
- 2026-11-06 — e5-small embeddings for all three chunkers (18,098 vectors, HNSW). Sanity query "CET1 ratio Vontobel 2025": table_aware returns the BIS capital ratios table (p7, CET1 19.7%) at rank 1; structure and fixed512 return prose pages about capital/risk, not the table, in their top 5.
- 2026-11-06 — Phase 2: 150-question dataset (100 dev / 50 test) built from seeded page sampling + LLM proposals + machine checks. Of ~330 proposals ~15% failed machine checks (mostly table_compute: model arithmetic or numbers not on page); 12+6 unanswerable proposals dropped after spotting related passages. Comparison needed 5x oversampling because most page pairs share no comparable metric. Spot check of 20 items by hand still to do.
- 2026-11-06 — Phase 2 spot check (20 items, blind, AI-assisted): 20/20 answers agree, 0 wrong, 9 strict-ok, 11 flagged ambiguous almost entirely because the same fact appears on several pages. Fix: `alt_pages` (59 automatic + 13 manual) instead of dropping items; q013 reworded. Test-set hash updated before any tuning.
- 2026-11-06 — Phase 3 Stage A (9 configs, e5-small, qa_dev, 90 answerable items): table_aware+vector best (R@5 0.67 [0.58,0.77], MRR 0.51), then table_aware+hybrid (0.61), structure+vector (0.49), fixed512 (0.40-0.41). Paired bootstrap: table_aware beats structure (+0.18 R@5) and fixed512 (+0.27) with vector retrieval; structure vs fixed512 not significant. FTS is weak everywhere (R@5 0.24-0.32) and hybrid does not beat vector (table_aware: R@5 not significant, MRR -0.11 significant; structure: hybrid R@5 -0.13 significant). Confound to test: table_aware chunks carry "Bank | Year | Section" in their text, so part of the gain may be implicit bank/year matching rather than table isolation.
- 2026-11-07 — Phase 3 ablation + Stage B (qa_dev, n=90). Header ablation (e5-small, vector): table_aware 0.67 R@5; table_aware WITHOUT its "Bank | Year | Section" header 0.48 (paired diff +0.19 [+0.10,+0.28]); structure 0.49; structure WITH the header 0.68 (+0.19 [+0.09,+0.29] over plain structure; vs table_aware +0.01 ns). So the earlier "table_aware wins" was the context header, not table isolation: without it table_aware is not distinguishable from structure (-0.01 ns) and only borderline over fixed512 (+0.08, CI [0.00,+0.17]). Embeddings on table_aware, vector: bge-m3 0.73 R@5 / 0.62 MRR, e5-large 0.68 / 0.52, e5-small 0.67 / 0.51; bge-m3 vs e5-small R@5 ns (+0.07), MRR +0.11 significant; e5-large = e5-small. Hybrid (RRF) never beats vector alone (bge-m3: R@5 ns, MRR -0.14 significant). Re-running e5-small configs reproduced Stage A numbers exactly.
